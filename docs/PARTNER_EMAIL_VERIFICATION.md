# Partner application email verification

The public partner form requires a Thaiseva email OTP before preview and submission. Send, resend and verify call the existing `asia-east2` functions; other food portal APIs remain in `asia-southeast1`. Codes and ten-minute proofs stay in memory. Changing the email resets verification.

Before sending or resending an OTP, `checkPublicPartnerEmail` checks the normalized email against Firebase Auth, restaurant contact emails, and pending or approved partner applications. Submission repeats these checks so skipping the frontend check cannot reuse an existing email. Rejected applications may reapply if no account or restaurant uses the address.

Configure `VITE_FIREBASE_APPCHECK_SITE_KEY=6LcWPHotAAAAACfAvmhyrUMFTkgKXgfnyIKtSI2y` using the registered gothai-foodporatal web app in Firebase project `gothai-ffea1`. Production domains must be authorized for the reCAPTCHA Enterprise provider. For localhost, register the App Check debug token generated by the existing development initialization. Never ship a debug token in production.

The `submitPublicRestaurantApplication` function binds the existing Secret Manager secret `OTP_HASH_KEY`. This must be the same secret used by the OTP service, not a newly generated key. Ensure it exists in this Firebase project and the function service account can access it before deploying. Never put it in Vite environment variables.

Submission checks proof expiry, email binding and consumption, then consumes the proof and writes the application together in a Firestore transaction. The proof collection must remain inaccessible to clients. Accepted applications record `emailVerified` and `emailVerifiedAt`. An identical submission retry with the original proof and application ID returns the existing result.

Deploy the updated backend and frontend together. Manually verify email delivery, wrong-code rejection, resend countdown, old-code rejection after resend, email-change reset, expiry, and a successful partner submission on an authorized domain. The automated proof validation tests run with `node --test tests/emailVerification.test.cjs`.

Provider setup: [Firebase App Check documentation](https://firebase.google.com/docs/app-check/web/recaptcha-enterprise-provider). Secret binding: [Firebase Functions configuration](https://firebase.google.com/docs/functions/config-env).
